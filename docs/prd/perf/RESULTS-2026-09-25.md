## Regressions found in this run, fixed in source (need another server rebuild)

1. **Opening the 15 MB session was still 1.7 s.** The history request (7 ms alone) waited behind `GET /api/agent-relay/projects/:id/unlanded`, which blocked the event loop for ~600 ms. It spawned ~360 git processes at once (121 old relay jobs × `revParse` + `repositoryRoot` ×2 + `committedChanges`), and `child_process.spawn` is synchronous. Fix in `relay-delivery.service.ts`: the pathspec is resolved once per call, changed-file counts are cached per immutable `base..tip` range, and at most 4 jobs run concurrently. Measured on a DB copy: 650 → 140 ms total, event-loop block 600 → ~110 ms. The type-check is clean and relay tests pass (95/95).
2. **Large history pages were 15–35 ms slower on localhost** because of the new gzip middleware. Pages of 1–2 MB are mostly base64 images and compress only ~30%. Fix in `server/index.js`: skip compression for loopback peers (the local browser, and nginx, which gzips for the tunnel itself). LAN/Tailscale clients still get gzip.

## Still open
- Pre-warming Claude when a session is opened (`prewarmClaudeSession` exists but isn't wired) is what would fix the ~7 s cold first turn.
- Session-open still fires about 35 requests in parallel (all provider `/models`, relay jobs, skills, files, taskmaster). Deferring the non-critical ones until after the transcript renders is the next client win.
- Codex app-server reuse; nginx upstream keepalive; `UV_THREADPOOL_SIZE` is not yet in the plist.

### Remaining issues seen in round 2

It probably happens when the streamed row becomes the final message (full markdown + Prism highlight of the closed code block), but that isn't verified yet. It needs a profile.
- Cold first turn for **new** sessions (~8 s): pre-warm could fire on "New Session" once the provider session id exists, or keep one generic warm process per project.
- `claude/models` is still a 0.4–1.5 s CLI probe; it doesn't block anything.
